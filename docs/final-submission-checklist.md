# Deliverable 4 — Final Submission Checklist

## Application
- [ ] Public deployment is reachable.
- [ ] CRUD works end to end on the deployed application.
- [ ] Happy-path smoke test passes.
- [ ] At least one failure path is demonstrated.

## Presentation
- [ ] Problem explained.
- [ ] Solution explained.
- [ ] Architecture explained by following a request.
- [ ] Live demo uses the deployed URL.
- [ ] Backup screenshots/video prepared.

## Rehearsal
- [ ] Exact click-path rehearsed once from start to finish.
- [ ] Graceful failure included.
- [ ] Each member knows their presentation part.

## Defense
- [ ] Each member can explain their own code.
- [ ] Each member can explain invalid input handling.
- [ ] Each member can explain missing-record handling.
- [ ] Each member can identify where validation lives.
- [ ] Each member can state one improvement.

## Database
- [ ] Current datastore choice explained accurately.
- [ ] MySQL schema/ERD available as the planned relational design.
- [ ] If using MySQL in production, connection/configuration and migration evidence are recorded.

## Evidence
- [ ] docs/retrospective.md complete.
- [ ] docs/deployment.md contains the real public URL and deployment notes.
- [ ] Board ownership is visible.
- [ ] Commit history shows each member's contribution.
- [ ] Reviewed PRs are documented.

## AI rule
The Week 12 oral defense is AI OFF and unassisted. Do not use AI assistance during the actual defense.
